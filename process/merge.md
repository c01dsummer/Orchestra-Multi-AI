# 批准与合并

1. 平台对接角色现查合并请求的目标分支、待合并版本、自动检查状态和跨家复审记录，写明查询时间。
2. 自动检查必须全部通过，跨家复审必须通过且覆盖当前版本，阻断项全部关闭；有任一条件未满足就退回对应角色。
3. 审批角色向使用者提供改动全文或可直接访问的完整内容、检查摘要、复审结果、影响与推荐理由，请使用者明确批准该合并请求及版本。沉默和超时不算批准。
4. 执行前再次核对版本与批准范围。只有自动检查通过、跨家复审通过、使用者明确批准三项同时满足时才能合并。执行合并的人员或平台对接角色均必须未参与该变更编写，且已获使用者明确批准；若平台对接角色参与了编写，必须交由其他未参与编写且获明确授权的角色或人员执行。批准后有新改动则重新复审和确认。
5. 记录合并结果并交接。涉及技能或配置时，配置管理角色按 `process/sync.md` 同步，调度角色抽查版本。

禁止自行合并自己的改动，禁止绕过分支保护，禁止强推覆盖保护分支历史。合并授权不包含删除、重写历史或发布等额外动作；这些事项另交使用者决定。
