# 派工与接活

1. 调度角色确认需求、范围、验收条件、依赖和使用者授权。沿用使用者现有任务系统登记或核对任务编号，后续运行与交接使用同一编号，不另建平行待办。
2. 读取 `config/team.json`，按 `role` 选定承担者，核对其 `engines` 与职责。缺少配置或没有合适角色时报告使用者，不猜名字或权限。
3. 读取 `config/rules.json`，按任务类型选择路由与候选顺序；核对引擎在承担者可用列表中。复审任务还须先按 `reviewers` 排除全部作者引擎。
4. 派工写明：任务编号、需求和验收条件、角色及承担者、候选引擎、模型和强度（未指定则采用该引擎默认值）、替补条件、预期产出、下一角色。
5. 接手角色确认范围与阻塞后执行。每次调用都记录实际引擎和模型，失败与替补同样记录。质量不过先按该路由的专门规定处理，不能擅自换候选。
6. 完成或受阻时按 `process/handoff.md` 交接；候选耗尽、额度不足、规则冲突等交审批角色汇总。

派工示例：`任务 DEMO-1｜角色 开发｜承担者 代码员｜路由 写代码｜首选 engine-alpha｜验收 本地检查通过｜下一角色 复审`。模型实际名称须从使用者工具确认，示例引擎不能直接调用。
