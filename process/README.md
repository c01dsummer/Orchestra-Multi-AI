# 协作全链路

| 阶段 | 接手角色 | 产出与进入下一步的条件 |
|---|---|---|
| [派工与接活](dispatch.md) | 调度 → 开发或调研 | 已确认的任务编号、范围、验收条件、角色和路由 |
| [执行与交接](handoff.md) | 执行角色 → 下一角色 | 产出、自检、完整作者引擎与模型记录、阻塞及待办 |
| [跨家复审](review.md) | 复审 | 合规非作者引擎的分级结论，阻断项修复后再审通过 |
| [批准与合并](merge.md) | 审批 → 平台对接 | 自动检查通过、跨家复审通过、使用者明确批准 |
| [改规矩](change-rules.md) | 配置管理 | 正本分支与合并请求、检查证据、使用者批准、配置版本更新 |
| [正本同步](sync.md) | 配置管理，调度核对 | 检查、备份、覆盖、版本核对与抽查 |
| [统一任务关单标准](ticket-closure.md) | 执行角色 → 复审及项目决策人，调度跟踪 | v1.0（D1–D6）：三种终态、10 类卡型、L0/L1/L2 证据及既有回执扩展；完成适用验收或有效取消/重复裁决 |

用量角色贯穿各阶段提供额度提醒；审批角色汇总无法继续的决策点。调度角色跟踪交接和版本一致性。通用技能正本与配置正本分别维护，抄本只接收批准合并后的内容。

关单标准按项目采用记录的生效日用于新建或新关闭的任务单，不追溯历史已结任务单；文档入库不代表项目已经完成推广。非仓库交付按卡型验收，需要合并或同步的交付须完成相应流程再判定终态。

模型调用执行器不随技能提供。没有包装程序时，助手照规则表选模型，并人工或用自有脚本核对作者记录与跨家复审条件。完成通知组件只报告运行结束，不代表质量通过或批准合并。
