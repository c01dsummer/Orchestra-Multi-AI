# 改规矩

1. **提出改动。** 写明任务编号、原因、完整差异、影响对象与回退办法。先查看现有待办，优先合并、拆分或调整顺序，沿用使用者的任务系统。
2. **修改正本分支并开合并请求。** 通用技能改本仓库正本分支；名单、规则表和设定全文改配置正本分支。配置管理角色准备改动，推送与开合并请求遵守使用者的授权范围；不直接改抄本。
3. **跑格式与隐私检查。** 在技能根目录运行 `bash scripts/check.sh`，按部署方式提供禁用词；运行相关测试和 CI。规则表格式变更须同时更新格式说明、空白模板、示例和检查契约，配置正本也要补齐。按 `process/review.md` 跨家复审，阻断项修复后再审。
4. **使用者批准合并。** 提供可审阅的全文、检查与复审证据，按 `process/merge.md` 获得明确批准并合并。未批准的内容不生效。
5. **升级配置版本号并同步抄本。** 配置改动记录中的下一版本及说明应随合并请求一起审阅，合并后确认该版本生效，再按 `process/sync.md` 备份、同步、抽查。不在合并后直接修改受保护分支。通用改动记录独立维护；仅改路由内容不递增规则表格式字段 `version`。

如果需要升级规则表格式，先安装兼容新版本的自备执行器并试跑，再换表。发现异常先恢复备份，通过新的合并请求修复正本，禁止私改抄本掩盖差异。
