# 统一任务关单标准（DoD）

规范版本：**v1.0（D1–D6 修订版）**。DoD 指任务完成定义。本规范说明如何判定任务终态，沿用项目已有任务系统、状态词典和验收要求。

## 1. 版本、采用与生效

通用规范正本位于本文件，修改按 [改规矩](change-rules.md) 复审、批准合并并记录版本。团队阈值、角色映射与项目专用验收留在使用者的私有配置或项目规范中，采用记录引用本文件版本，不复制整篇规则。

“项目决策人”对应项目中的人类负责人（使用者），其裁决由使用者直接作出或经 [审批角色](../roles/审批.md) 按规转达；明确授权人须有可追溯的授权记录，且仅在授权范围内裁决。明确授权人作范围、取消或风险接受裁决时，不得是本卡的执行者或承接人（人类负责人本人作出的裁决不受此限，但须记录；没有独立人类负责人的单人维护项目，由维护者本人承担人类负责人职责，须在项目采用记录中写明并保留自审与结单证据）。超时、无人回复或静默一律不视为批准。

采用分阶段进行：先将通用正文版本化；再由项目决策人（人类负责人或其明确授权人）批准采用，在已纳管的设定模板中加入读取入口，统一生成并推广；最后逐个读回核对入口、版本和状态字段一致。**项目生效日为推广完成且读回一致之日**，采用记录须写明规范版本、生效时间及时区、授权来源和核对证据。文档入库日期不自动成为项目生效日。

仅对生效日之后新建或新关闭的任务单执行，包括生效前创建、生效后才关闭的任务单；不追溯存量历史已结任务单。历史终态和裁决记录保留，后续补证据不改写当时事实。

本规范供人和助手读取。没有实际运行时读取方时，不向配置 Schema 添加关单字段；后续若实现关单检查器，再明确字段、读取方与验收。本文不表示已实现自动关单拦截。

## 2. 三种终态及范围权限

| 终态 | 成立条件与证据 | 不足以单独成立的依据 |
|---|---|---|
| `Done` | 批准的范围已交付，原 DoD 每项均已验收，或按 D1 在同时具备项目决策人明确范围裁决记录与明确去向（关联已建立且承接范围明确的有效后续任务单，或经项目决策人明确批准不再执行）后移出、延后或缩减；产物及版本可追溯，按档位和卡型要求的独立复审与适用检查通过，所需接受、合并、发布或同步已有证据；在既有回执记明结单人与带时区时间 | 仅运行结束、退出码为零、开 PR、单次 CI 通过、复审服务卡完成、新建后续卡，或一句“已完成” |
| `Canceled` | 项目决策人明确批准取消，记录原因类别、事实或替代决定、决定人及时间；列明取消的未做范围、每项无需承接的裁决理由或有效承接任务单、已有产物保留位置，以及父子、关联和阻塞关系的清理结果 | 仅更换执行者、排期暂缓、额度不足、无人回复、草稿已交，或声称“新规取代”但原义务仍存在 |
| `Duplicate` | 必填重复目标字段（如 `duplicateOf`）；目标当前有效、不是自身且关联链无环；原 DoD 到目标逐项 **100% 覆盖**，目标负责人确认承接，原证据与评论已回链，记录查询时间及关联复查责任 | 仅主题相近、修改同一文件、同属母卡、同一设计记录链上的不同义务、覆盖不全，或指向已 `Canceled` 的目标 |

终态只描述本卡批准范围。调研、决策或登记完成，不代表相关工程已经实现；`Canceled` 不等于交付完成，`Duplicate` 不等于另一种 `Done`。暂缓且仍需交付的任务保持项目定义的未结状态，并写明等待项、负责人和复查时间。

### D1：移出、延后或缩减原 DoD 的权限

从原任务 DoD 移出、延后或缩减交付项，**必须同时满足两个条件**：一是须有项目决策人（人类负责人或其明确授权人）的明确范围裁决记录；二是被移出项须写明去向——要么关联已建立且承接范围明确的有效后续任务单，要么经项目决策人明确批准不再执行。裁决记录写明授权来源、范围版本、具体移出项、理由与去向；有效承接任务单须符合项目既有移交授权，写明对应原 DoD、实际负责人及其接受记录、承接范围和验收条件，且当前有效、能够追踪交付。仅创建一张后续卡不构成有效承接。

任何范围移出、延后或缩减均须先取得项目决策人明确裁决；执行者或承接人不得仅因挂了后续任务单就自行移出范围并以 `Done` 结单。执行者不得以“非阻塞”“以后再做”自行降级原承诺，也不得在结单时把未完成项默认为范围外。范围有歧义或承接无人确认时，保留未结状态并交项目决策人裁决。取消范围也须满足 `Canceled` 的批准条件；合法承接不代表被移出的工作已经完成。

### D3：重复必须完全覆盖，并持续复查

标记 `Duplicate` 前逐条核对原 DoD 与目标的对应项及验收条件，不得只比较标题。目标可以仍在执行，或已经交付并有完整验收证据，但不能已取消、失效或仅指向无有效承接的重复链。

**覆盖不足 100% 不得标 `Duplicate`，应改为 `Canceled` 并写明已承接与未承接部分的去向**；该改判仍须先取得取消裁决，未获批准前保持未结。未承接项须有其他有效承接，或由项目决策人明确批准不再执行，不能悄然丢失。

当工单按 `Duplicate` 结单或建立承接关联时，目标任务归属调度维护或巡检范围的，由调度登记反向关联及复查责任，并在每次例行巡检中复查；目标不在调度巡检范围内的，由发起 `Duplicate` 或承接关联的操作人直接登记反向关联及复查责任，按“依赖/在等”记录的带时区复查时间及在目标任务状态变更或结单前手动查询复查，直至目标任务到达 `Done` 且覆盖关系核对通过为止。目标状态或范围变化时，按登记的复查责任核对依赖它的重复卡。**目标变为 `Canceled` 必须触发联动重判**；缩减范围、失效或承接断裂同样重判。核对新的有效目标及全量覆盖，必要时重新打开原卡，或按授权更正终态并保留历史。已部署的工具可发现并提示变化；没有工具时由登记的复查责任人手动查询，不把无人监控视为关系有效。

## 3. D4：唯一的 10 类任务卡型枚举

规范表、状态字段和回执只使用下表十个完整名称。复合任务选择一个主卡型并叠加所有适用证据；不能通过更换卡型免除原 DoD。

| 卡型 | `Done` 不可替代的证据与边界 |
|---|---|
| 代码/配置实现 | 仓库交付须有目标分支已合并的 PR、合并提交与验收树，适用测试、CI 和覆盖该版本的跨家复审；仓库来源的配置同步须有批准 PR 链接、合入 commit SHA 及目标路径读回核对；非仓库配置交付须有明确操作授权记录、配置版本、批准源版本及适用的跨家复审；范围内的发布、同步一并验收。配置同步（无论来源是否为仓库）均须另列批准源版本、完整目标清单、备份、逐项差异与读回核对，确认所有读取方一致；只验证清单内文件不能证明清单没有遗漏；清理须写明清理前后状态与保留原因 |
| 缺陷修复 | 原问题及可复现场景、修复后验证与相关回归、目标分支合并版本及独立复审，确认阻断项关闭；不能只转建任务单便声称缺陷已修复 |
| 架构/方案设计 | 有限设计范围、约束、备选及取舍、接口或迁移边界、方案版本与适用复审、接受记录；设计交付不包含未获批准的实施承诺 |
| 方案拍板 | 全部必决项的选择、拒绝或明确暂不选择，决定人、授权来源、时间、版本、理由、责任边界与后续去向；仅发出待决卡不算拍板，决定暂不实施也不代表实施已完成 |
| 调研/分析 | 有限问题清单及逐题答案、来源和检索时间、证据边界、可定位的产物版本，模型运行与核验记录或未调用原因，必要的接受结果；否定或不可行可以是完成结论，落地实施另行定范围 |
| 高风险调研/引用核对 | 调研/分析的全部适用证据，加 D2 的风险三要素、合规跨家独立复审记录及关键结论四栏核对表；未核实、相互矛盾或不支持的引用必须显式处理 |
| 独立复审服务 | 被审版本、全部作者集合、合规非作者审方及运行和报告、分级发现、覆盖边界与接收人；报告含阻断项仍可完成本次复审服务，但被审产物不能因此视为通过 |
| 平台能力验证 | 支持或不支持的结论及实证、平台或接口版本、验证条件与边界；需要试点执行时先取得批准，收益只认实测，不支持也可作为验证完成结论 |
| 文档/ADR/欠条登记 | 批准范围内的正式产物和版本，仓库交付须合入；来源、分档、重启条件、原记录与后继关联可追溯，适用校验及独立核验通过；登记完成不等于技术欠项已解决，任务单不自动替代 ADR |
| Epic/有限母卡 | 冻结的有限子项清单与范围版本、各子项合规终态到母卡 DoD 的映射、适用的总体整合或端到端验收；取消或重复子项不能丢失母卡义务，首片完成不代表整体完成。持续工作线使用长期容器，新发现另立范围 |

进入集成分支或准备就绪仍属中间状态；要求进入目标主干的交付，须等实际合入再验收。修改仓库正本的配置仍须遵守 [改规矩](change-rules.md) 和 [批准与合并](merge.md) 流程。以下两类工作按实际交付归入上述卡型，复合任务仍按主卡型叠加证据，不另增同义卡型：

- **评测/数据跑批**：以评测结论或数据分析为交付时归入“调研/分析”，涉及高风险调研或引用核对时归入“高风险调研/引用核对”；以平台或接口实证为交付时归入“平台能力验证”，涉及代码或配置交付时叠加“代码/配置实现”的证据。须冻结数据集、任务/提示、运行配置及评分版本，并按评测矩阵逐格记录实际引擎、模型全名与强度（effort）、运行标识及原始数据/产物定位；未运行、失败或不适用的格须说明，不能用计划模型代替实际记录。
- **条件/风险跟踪**：以条件、风险及复查记录为交付时归入“文档/ADR/欠条登记”；涉及风险接受或处置裁决时叠加“方案拍板”的证据。须记录触发/解除条件、条件核验结果与证据、复查责任；关单或风险接受须有项目决策人的明确批准记录，不能以登记完成代替风险解除。触发高风险判定时同时满足第 4 节。

## 4. D2：高风险结单硬条件

风险等级按项目批准的风险规则判定；用途、触发项或等级不清时先补判定，不自行按普通风险放行。任何触发高风险判定的任务，结单前须具备以下适用证据，不能用普通自检或一句“已复审”代替：

1. **风险判定三要素**：在既有风险字段中写明用途、命中的触发项及其规则来源、风险等级；记录判定人和时间。与风险有关的范围变化须重新判定。
2. **合规跨家独立审方复审记录**：角色明确为复审，高风险级别明确，记录实际引擎、模型、强度、运行及报告、被审版本、结论和覆盖范围。按 [跨家复审](review.md) 汇总全部作者引擎（包括失败、替补及参与修复的运行），取各作者 `reviewers` 允许列表的交集，再排除作者引擎；审方不得属于作者集合，同家换模型不算独立。缺作者记录、无合规审方或复审未完成时保持未结并报告项目决策人，不能以额度或排期为由降级。
3. **高风险调研关键结论四栏核对表**：凡包含高风险调研或引用结论，逐条列出下表；独立审方核对原始证据及精确定位，标明属实、部分支持、不支持或未核实，说明证据边界和遗留问题去向。无引用性调研的高风险任务仍须满足前两项，并说明四栏表不适用的原因。

| 关键结论 | 引用定位 | 核对结果 | 遗留问题 |
|---|---|---|---|
| 每项影响决策或验收的具体结论 | 来源、版本或访问时间、章节/行号/页码等精确位置 | 核对判断、独立审方及证据边界 | 无，或问题、影响、负责人和处置关联 |

`Done` 要求影响本卡 DoD 的阻断项关闭，复审覆盖最终版本。`Canceled` 或 `Duplicate` 的高风险复审应覆盖取消/承接决定、未完成范围及风险处置，不能声称未做的实施已经验收。原高风险产物已有关键结论时，改为其他终态也不能省去引用核对。

## 5. D6：L0 轻量 / L1 标准 / L2 严格

按最高适用档执行，顺序为 L2 → L1 → L0；档位减少重复填写，不降低终态、授权或卡型的证据条件。

| 档位 | 适用条件 | 本次结单必填内容 |
|---|---|---|
| `L0 轻量` | 普通风险、单一交付、无范围变更、非母卡，且不触发 L1 或 L2 | **4 项**：卡型、一句话 DoD 结果、证据链接、结单人与时间 |
| `L1 标准` | 涉及仓库合入、需跨模型复审或含多项交付，且不触发 L2 | L0 加作者与复审记录、验收结果、残余项去向 |
| `L2 严格` | 高风险、Epic/母卡、配置同步、范围移出、延后或缩减、取消或重复，命中任一项即适用 | 完整字段映射与 DoD 逐项覆盖矩阵；高风险调研另加四栏核对表 |

跨模型复审仍遵守跨家约束；同一家换模型不能满足独立复审。没有模型产出的任务可在作者与模型复审记录中写“不适用”并说明原因；不能据此豁免高风险复审或其他明确要求的独立核验。无业务产物的引导卡可用一句话说明取消原因，但取消批准、剩余范围和关系清理仍须可追溯。

## 6. D5：扩展既有状态块与回执

本节是**字段映射**，不是要求另建模板块。结单回执必须扩展项目既有状态块与回执结构，复用 [交接](handoff.md) 中已有的任务、版本、作者、复审和证据字段；保留项目原字段名称、布局和历史。风险三要素放进原风险字段，终态放进原状态及回执结果字段，不另起一份“关单状态”或平行回执。

若项目未单独约定状态块或完成回执模板，默认以 [交接记录](handoff.md) 作为结单回执与证据载体，不另造平行模板。

项目采用记录可定义 `Done` / `Canceled` / `Duplicate` 到实际项目状态及关闭原因的映射，或直接使用 [交接记录](handoff.md) `当前状态` 所列终态。关闭时，当前状态与回执结果须按同一映射记录同一终态结果；映射所需的关闭原因一并保留，不得将取消或重复记为交付完成。

项目卡片已有分节结构（或项目约定的等价小节）的，将相应字段映射回原有小节，只补缺项，不新增必填小节，也不另建平行回执。L0 在原回执中补四项即可，卡内原有身份、状态和风险字段继续复用，无需重复抄写。以下完整映射供 L2 使用；L1 只补其规定字段。

```text
映射至项目原有状态块（在原位置补齐，不新增第二个状态块）：
卡型：选用第 3 节唯一枚举的一个完整名称
档位：L0 轻量 / L1 标准 / L2 严格
负责人：一位实际负责人；优先级：项目既有值
需求/范围版本：版本；来源决定及授权：链接；范围外：有限列举
风险：用途；触发项及规则来源；风险等级；判定人/时间
DoD：逐项可检查结果及所需证据；L2 在原位置附覆盖矩阵
依赖/在等：关联任务或外部事件；解阻人；带时区复查时间
关联：父子关系、有效承接、重复目标字段（如 duplicateOf；适用时填写）及反向复查责任
当前状态/终态：按项目采用记录将 Done / Canceled / Duplicate 映射到实际项目状态及关闭原因，或直接使用交接终态词典
接受或裁决：决定人、授权来源、决定链接与时间

映射至项目原有回执（复用原事件、结果、摘要和证据字段）：
事件：本次交付/取消/重复裁决
结果：按与当前状态相同的映射记录同一终态结果，保留所需关闭原因，不另维护第二份当前状态
摘要：一句话 DoD 结果；取消或重复时说明对应理由与承接边界
证据/产出：PR、目标分支、合并提交和验收树，或文档版本/平台读回链接
作者与复审：全部作者、实际引擎/模型/运行、审方资格、覆盖版本与分级结论
验收：适用测试/CI/实际验证、接受结果、未验证范围
残余：源 DoD 或新发现、影响、裁决、有效承接或批准不再执行的理由
取消专用：原因类别、事实/替代决定、未做范围、产物保留及关系清理
重复专用：重复目标字段（如 duplicateOf）、目标有效性及查询时间、100% 覆盖、承接确认和回链
收尾前查新评论：查询时间、新增要求与裁决处理结果
结单人与时间：实际操作人、带时区时间
```

L2 的矩阵附在原 DoD 所在位置；每个原范围项占一行，不能用总结代替逐项对应：

| 原 DoD 项及范围版本 | 对应产物/目标 DoD 与证据定位 | 结果 | 裁决或承接及负责人 |
|---|---|---|---|
| 一项可验收承诺 | 已交付版本，或承接目标的具体对应项 | 通过 / 未满足 / 经批准移出 / 经批准取消 / 完全承接；仅 `Canceled` 的不适用项记为“不适用”并说明原因，且不得免除对应终态的范围与覆盖要求 | 按适用终态提供决定与授权记录、有效承接链接及接受记录；范围移出、延后或缩减须同时有项目决策人明确范围裁决记录与明确去向（关联已建立且承接范围明确的有效后续任务单链接及接受记录，或项目决策人明确批准不再执行的记录） |

`Done` 终态各行结果只能为“通过”或“经批准移出（含延后、缩减）”；原 DoD 项如确属不适用，视同范围变化，须按“经批准移出”履行 D1 的裁决与去向登记。`Done` 工单的 D1 交付物类型若经批准移出当前工单，结果栏记为“经批准移出”，注明不适用原因并触发 L2；`Canceled` 工单不适用项结果栏记为“不适用”并说明原因。`Duplicate` 不设“不适用”行；原 DoD 项确属不适用时，须先按 D1 取得范围裁决，或按 D3 改判 `Canceled`。“完全承接”仅用于 `Duplicate`，或 `Canceled` 中已获项目决策人批准的承接项。

`Done` 不得含未满足项；`Canceled` 必须说明所有未做项的去向；`Duplicate` 每行都须完全承接，不能拿经批准取消或部分覆盖凑成 100%。风险四栏表按第 4 节附于原证据区域。

## 7. 结单前核对与责任

1. 执行者现查任务正文、新评论、需求版本及产物状态，确认卡型、风险和最高适用档位；出现新增要求先澄清范围。
2. 在既有状态与回执内补证据，按三种终态和卡型逐项判断。需要仓库合入时确认 PR 是已合并而非仅关闭、目标分支正确、合并版本与验收树相容；范围内要求同步时附 [同步](sync.md) 读回结果。
3. 复审角色按需核验最终版本及高风险硬条件；项目决策人处理接受、范围、取消等裁决。检查通过不替代 [批准与合并](merge.md) 的明确授权，关单回执也不能提前宣称尚未完成的合并或发布。
4. **跟进与反向关联登记**：需要后续处理的，先建好跟进任务或准备交接材料；由操作人准备残余项交接，并按第 2 节 D3 完成反向关联登记与复查，直至目标任务到达 `Done` 且覆盖关系核对通过；不能只写“后续再看”。结单人核对原状态、回执结果、父子和阻塞关系一致后记录终态；目标取消、失效、缩减范围或承接断裂时按 D3 联动重判，防止原工单悬空。发现状态冲突或证据缺失时暂停结单并补齐，保留历史更正记录。

若后续接入自动检查，可检查字段完整性、版本和合并事实、重复链有效性与无环、目标取消事件、母卡映射及残余去向，并将目标变化交给已登记的复查责任人联动重判。范围是否完全覆盖、调研是否回答原问题、范围裁决是否有效，仍需人或独立审阅作语义判断；自动检查全绿不能替代这些判断。
