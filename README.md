# Orchestra-Multi-AI：让多个 AI 助手分工协作

给同时使用多个 AI 助手的人准备的通用协作技能：分清角色、派工与交接，按规则表选模型，跨家复审，批准合并后同步正本。

## Stage 1（方案一）的边界

本仓库公开协作 Skill 及辅助组件：技能入口、8 类角色模板（`roles/`）、7 项协作流程（`process/`）、跨家复审与路由规则表规范（`routing/`）、完全虚构的团队示例（`examples/`）、本地自检与导出脚本（`scripts/`），以及运行完成通知守护组件（`tools/run-done-watcher/`）。

**调用各家模型的命令行执行器或包装脚本由使用者根据自身环境自备，执行器保持私有，不随本仓库分发。**

- 没有专用包装程序：助手直接按 `config/rules.json` 选择引擎、模型及强度，人工或用自有脚本核对全部作者记录与跨家复审。
- 有自有包装程序：可读取 `version` 与 `reviewers` 强制校验格式版本、作者引擎及互审配对。`routes` 由助手遵守，执行器是否支持自动路由由使用者自行决定。
- 可选通知：让自备执行器写出符合组件字段约定的运行记录，用 `tools/run-done-watcher/` 监控并发送完成通知。运行结束不代表质量通过或获得合并批准。

通用技能正本是本仓库的 `main`；真实团队配置在使用者自己的私有仓库维护，安装时放在被忽略的 `config/`。技能安装目录、执行器读取的规则表、线上设定均为抄本，只从批准合并后的正本同步。

## 安装与自检

需要 Bash、Python 3.10 或更新版本；克隆需要 Git，解压导出包后自检不依赖 Git。通知组件使用 Python 标准库及 Unix 文件锁，运行环境须支持该文件锁。

1. 克隆本仓库，目录命名 `orchestra`，放到助手可读取的技能目录；目录应包含完整技能包。

   ```bash
   git clone '〈仓库地址〉' orchestra
   cd orchestra
   ```

2. 尚无 `config/` 时，以示例生成本地配置起点：

   ```bash
   cp -r examples config
   ```

3. 修改 `config/` 中的名单、引擎、规则、项目及设定全文，详见 [示例说明](examples/README.md)。引擎与模型名称全部是虚构值，真实调用前必须替换。私有配置可单独纳入版本管理；密钥、登录内容和本机路径不写入任何文件。
4. 在仓库根目录运行以下命令，全部通过再启用：

   ```bash
   bash scripts/check.sh
   ```

5. 在每个助手设定中加入「开工前先读技能 `orchestra`」，结合 [角色模板](roles/README.md) 填好完整设定。让各助手报告名字、角色、配置版本和可用引擎，确认与正本一致。

未创建 `config/` 时，自检明确提示并校验示例；这只证明通用包完整，实际接活仍需配置。已创建时同时检查本地配置，示例与空白模板始终校验。空白模板允许占位符，示例和本地规则表不允许。

禁用词以多行文本从环境变量 `ORCHESTRA_PRIVATE_WORDS` 提供，未设置时读取 `config/private-words.txt`，均按大小写不敏感的字面子串匹配。未提供时明确提示仅跳过自定义禁用词检查；密钥形态和本机路径始终扫描。演示词表的自匹配处理见 [示例说明](examples/README.md)。错误不回显敏感内容。

## 角色与五步用法

| 角色 | 职责 |
|---|---|
| 调度 | 巡检进度、按职责派工、核对交接与规则表抄本 |
| 开发 | 按规则表编写代码或配置、自检、请求跨家复审 |
| 复审 | 使用非作者引擎独立检查，给出分级结论并闭环阻断项 |
| 调研 | 检索、方案对比、评测和长文档撰写 |
| 平台对接 | 跟踪合并请求与检查，按使用者明确批准合并 |
| 审批 | 提供选项全文、取舍和建议，记录使用者决定 |
| 用量 | 统计消耗与配额，在阈值和重置时提醒 |
| 配置管理 | 维护配置正本及设定全文，批准合并后同步抄本 |

入口 [SKILL.md](SKILL.md) 保留五步：读名单找角色 → 读角色职责 → 按规则表选模型 → 按流程协作 → 按流程改规矩。四条底线：复审不用作者用过的那家引擎；不自行合并自己的改动；改规矩走流程；密钥与本机路径不进任何文件。

## 协作、改规矩与同步

- 从 [派工](process/dispatch.md) 开始，执行后按 [交接](process/handoff.md) 写清任务编号、产出、实际引擎与模型、待审版本及下一角色。
- [跨家复审](process/review.md) 依据全部作者的 `reviewers` 交集选引擎；同一家换模型仍算自审，失败的作者运行也计入。质量不过先修复再审，不能靠换引擎换结论。
- [合并](process/merge.md) 同时要求自动检查通过、跨家复审通过、使用者明确批准。禁止强推覆盖保护分支历史；平台的保护设置由使用者按环境配置。
- [改规矩](process/change-rules.md) 修改正本分支，按授权开合并请求，跑检查并复审，使用者批准合并后确认配置新版本生效，再 [同步](process/sync.md)。配置管理负责检查、备份、覆盖和核对，调度抽查；异常先恢复备份再提合并请求修复。
- [统一任务关单标准](process/ticket-closure.md) v1.0（D1–D6 修订版）定义 `Done` / `Canceled` / `Duplicate`、10 类卡型及 L0/L1/L2 证据要求，结单回执扩展项目既有结构。项目记录采用版本和推广读回后的生效日，不追溯历史已结任务单。

Stage 1 提供同步流程说明；线上目标和复制工具由使用者自备。配置版本取自 `config/CHANGELOG.md`；规则表的 `version: 1` 表示格式版本，仅修改内容不升级该字段。

## 导出与通知组件

在根目录运行：

```bash
bash scripts/export.sh
# 或指定输出文件（父目录须已存在）
bash scripts/export.sh orchestra-share.tar.gz
```

默认生成 `orchestra-v1.tar.gz`，已有同名文件时报错。导出前先自检，只打包 `scripts/export.sh` 逐项列出的公开文件；发现清单外的源文件时拒绝导出。`.git`、`config`、缓存、运行状态和构建产物按自检相同边界忽略，均不打包。新增公开文件时须同步更新清单。导出包以 `orchestra/` 为顶层目录，解压后可直接运行自检。

通知组件见 [使用说明](tools/run-done-watcher/README.md)。原有接口和离线测试保留，新增标准测试发现入口：

```bash
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s tools/run-done-watcher -v
```

组件只读取运行记录，按环境变量提供的通知地址与请求头投递完成事件；真实值不写入配置或状态。它不调用模型，不负责派工、复审或批准合并。

## 贡献与隐私

通用角色、流程、格式和虚构示例可公开；真实团队、项目、账号与禁用词留在私有配置。公开部分不含私有执行器。不要把密钥、登录内容或本机路径写进任何文件，也不要把真实名单替换进 `examples/`。

修改通用内容走合并请求，更新 `CHANGELOG.md` 并通过格式、隐私及相关组件检查。CI 从仓库 secret 读取禁用词，从仓库变量读取规则表必填指针；新增公开规则表默认继承空白模板的必填契约，显式配置可覆盖。本地自检还严格检查类型、版本、重复键、配对与路由。检查通过不替代跨家复审或使用者批准。
