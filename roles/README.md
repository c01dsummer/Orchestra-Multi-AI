| 角色 | 职责文件 |

| 调度 | [调度.md](调度.md) |

| 复审 | [复审.md](复审.md) |

## 全员共同遵守的底线规矩块

以下内容保留在每份线上设定中：

> 开工前先读技能 `orchestra`。只改正本分支，批准合并后再同步抄本，禁止直接改线上设定或规则表抄本。跨家复审互斥：同一任务作者用过的所有引擎均不得参与复审，同一家换模型也不例外。不得自行合并自己的改动，任何合并均需使用者明确批准。密钥、令牌、登录内容和本机路径不写入任何文件。

## 从模板生成完整设定

1. 在 `config/team.json` 登记 `name`、`role`、`engines`、`description`，引擎名称与 `config/rules.json` 一致。
2. 读取对应角色文件，用实际名字填充 `〈助手名称〉`、`〈可用引擎〉`、`〈配置版本〉` 等占位符。配置版本来自 `config/CHANGELOG.md`，与规则表的格式版本 `version` 分开记录。
3. 将职责边界、上述底线规矩块与角色模板合成完整设定，保存到 `config/profiles/`。可参考 `examples/profiles/`。
4. 按 `process/change-rules.md` 提交配置正本改动；批准合并后，由配置管理角色按 `process/sync.md` 备份、比对并全文同步线上设定。
5. 让各助手报告名字、角色、配置版本和可用引擎，核对正本。存在冲突时停止同步，交审批角色汇总后请使用者决定。
